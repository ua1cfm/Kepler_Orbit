# Kepler Orbit

**Kepler Orbit** — Android-приложение для радиолюбительского спутникового слежения, расчёта орбит по TLE и управления антенным ротатором **Yaesu G-5500 / GS-232B**.

Текущая версия проекта: **0.1.89**  
Автор: **UA1CFM**

---

## Возможности

Kepler Orbit объединяет в одном приложении:

- загрузку и хранение TLE;
- расчёт положения спутников по **SGP4 / SDP4**;
- прогнозирование пролётов **AOS / MAX / LOS**;
- радар пролёта;
- 2D-карту Земли и 3D-глобус;
- одновременное отображение нескольких выбранных спутников;
- отображение текущих орбит и кругов радиовидимости;
- расчёт азимута, угла места, дальности и доплеровского сдвига;
- звуковые сигналы AOS и LOS;
- управление ротатором по **GS-232B**;
- подключение к контроллеру через **USB/OTG** или **Wi-Fi/TCP**;
- автоматическое сопровождение спутника;
- парковку ротатора после LOS;
- четыре режима ориентации 3D-глобуса: **TRACK / QTH / SUN / MOON**;
- несколько стилей карты, включая специальный **ORBITRON**.

---

# 1. TLE и расчёт орбиты

Приложение работает со стандартными TLE-наборами и использует их для расчёта текущего положения спутника.

Поддерживаются:

- 2-line TLE;
- 3-line TLE с названием спутника;
- открытие локального файла;
- загрузка TLE из Интернета;
- сохранение загруженного TLE между запусками.

## Источники TLE

В приложении доступны:

- **AUTO**;
- **R4UAB / satonline.txt**;
- **AMSAT-NA / nasabare.txt**;
- **CelesTrak / Amateur Radio**;
- **SATGS / satonline.txt**.

Режим **AUTO** использует резервную последовательность источников. Если один источник недоступен, программа может перейти к следующему.

## Возраст TLE

Kepler Orbit показывает, сколько времени прошло с эпохи наиболее свежих орбитальных данных в загруженном наборе.

---

# 2. Выбор спутника

Спутник выбирается из загруженного списка TLE.

Доступен поиск:

- по названию;
- по NORAD ID.

Выбранный спутник используется как основной для:

- текущего SGP4-расчёта;
- радара;
- 2D-карты;
- 3D-глобуса;
- ROTATOR;
- AUTO TRACK.

Основной выбранный спутник сохраняется между запусками приложения.

---

# 3. Наблюдатель и QTH

Можно задать:

- Latitude;
- Longitude;
- высоту наблюдателя;
- Maidenhead / QTH Locator.

Поддерживаются функции:

### USE MY LOCATION / LOCATOR

Получение координат через Android Location.

### APPLY QTH

Преобразование Maidenhead Locator в Latitude / Longitude.

### LAT/LON → QTH

Обратное преобразование координат в QTH Locator.

Координаты наблюдателя сохраняются между запусками приложения.

---

# 4. Текущие параметры спутника

Для выбранного спутника рассчитываются:

- подспутниковая широта;
- подспутниковая долгота;
- высота над Землёй;
- азимут;
- угол места;
- наклонная дальность;
- скорость изменения дальности;
- доплеровский сдвиг;
- геометрическая зона радиовидимости.

Доплеровский сдвиг рассчитывается для введённой пользователем рабочей частоты.

---

# 5. ORBIT / MAP

Основная страница визуализации содержит:

1. параметры наблюдателя и радио;
2. радар пролёта;
3. выбор вида карты;
4. переключатель количества отображаемых спутников;
5. 3D-глобус;
6. 2D-карту;
7. параметры орбиты;
8. текущее положение спутника.

---

# 6. Радар пролёта

Радар отображает траекторию спутника по небу относительно текущего QTH.

Показываются:

- азимут;
- угол места;
- траектория текущего или следующего пролёта;
- AOS;
- MAX;
- LOS;
- максимальный угол места.

Если пролёт уже идёт, отображается текущий активный пролёт.

---

# 7. 3D-глобус

3D-глобус отображает:

- Землю;
- текущую орбиту;
- спутник;
- подспутниковую точку;
- положение наблюдателя;
- круг радиовидимости;
- дополнительные выбранные спутники;
- орбиты дополнительных спутников;
- круги радиовидимости дополнительных спутников;
- геоцентрические радиальные линии от центра Земли к спутникам.

## Масштаб орбит

Орбиты отображаются пропорционально размеру Земли.

Используется геометрическое отношение:

`Rорбиты = RЗемли + высота спутника`

Искусственного увеличения высоты орбиты нет.

## Unified Auto Zoom

Масштаб 3D-сцены автоматически подбирается так, чтобы отображаемые орбиты помещались в окно.

Важно:

- масштаб применяется ко всей сцене;
- Земля и орбиты масштабируются одинаково;
- физическая пропорция Земля/орбита сохраняется;
- один и тот же принцип используется в TRACK, QTH, SUN и MOON.

## Разрыв начала и конца орбиты

Текущая орбита намеренно не замыкается прямой линией между первым и последним рассчитанным пунктом.

Начало и конец линии остаются свободными. Это исключает ложную хорду или перпендикулярный соединительный отрезок.

---

# 8. Режимы 3D-глобуса

На 3D-глобусе доступны четыре режима:

## TRACK

Центр видимой полусферы направлен на текущую подспутниковую точку основного спутника.

## QTH

Центр глобуса направлен на координаты текущего наблюдателя.

Таким образом:

- QTH находится в центре видимой полусферы;
- наблюдатель отмечается на карте;
- удобно оценивать положение спутников и орбит относительно своей станции.

## SUN

Центр глобуса направлен на подсолнечную точку.

Дополнительно отображаются:

- дневная сторона Земли;
- ночная сторона Земли;
- терминатор;
- подсолнечная точка.

## MOON

Центр глобуса направлен на подлунную точку.

Подлунная точка отображается отдельным маркером.

---

# 9. ONE SATELLITE / ALL SELECTED

Для 2D и 3D используется единый переключатель.

## ONE SATELLITE

Показывается только основной текущий спутник:

- одна текущая орбита;
- текущее положение;
- круг радиовидимости.

## ALL SELECTED

Показываются:

- основной спутник;
- спутники, выбранные во вкладке PASSES;
- текущая орбита каждого спутника;
- текущее положение каждого спутника;
- круг радиовидимости каждого спутника.

Для каждого спутника отображается **только одна текущая орбита**.

Будущие витки и будущие пролёты как дополнительные орбиты на карте не рисуются.

---

# 10. Круги радиовидимости

Для каждого отображаемого спутника рассчитывается собственный геометрический круг радиовидимости.

В режиме **ALL SELECTED**:

- цвет круга дополнительного спутника соответствует цвету его орбиты;
- круг обновляется вместе с текущим положением спутника;
- отображение работает и в 2D, и в 3D.

---

# 11. Геоцентрические радиальные линии

В 3D-режиме отображается линия:

**центр Земли → спутник**

Для основного спутника линия выделена сильнее.

Для дополнительных спутников используются более тонкие цветные линии.

Линии работают во всех режимах:

- TRACK;
- QTH;
- SUN;
- MOON.

---

# 12. Стили карт

Один выбранный стиль используется одновременно:

- на 2D-карте;
- на 3D-глобусе.

Доступны:

## STANDARD

Стандартная встроенная карта.

## POLITICAL

Политическая карта.

## POLITICAL COLOR

Цветная политическая карта с различной окраской стран.

## NASA

Карта Земли на основе спутниковой текстуры NASA.

## CONTROL

Тёмная карта в стиле диспетчерского / командного центра.

## ORBITRON

Специальный стиль, визуально напоминающий классические спутниковые программы:

- чёрный фон;
- синие материки;
- синяя координатная сетка;
- одинаковая текстура для 2D и 3D.

`ORBITRON` является стилем отображения Kepler Orbit и не означает официальную связь проекта с программой Orbitron.

---

# 13. 2D-карта

На 2D-карте отображаются:

- текущий ground track;
- основной спутник;
- дополнительные выбранные спутники;
- текущие орбиты выбранных спутников;
- круги радиовидимости;
- положение наблюдателя.

Корректно обрабатывается переход орбиты через границу:

`+180° / -180°`

что предотвращает появление ложных длинных линий через всю карту.

---

# 14. PASSES — прогноз пролётов

Приложение рассчитывает будущие пролёты выбранных спутников.

Можно выбрать несколько спутников одновременно.

Для каждого пролёта отображаются:

- дата;
- AOS;
- MAX;
- LOS;
- максимальная высота;
- азимут AOS;
- азимут MAX;
- азимут LOS;
- длительность пролёта.

Список сортируется по времени AOS.

Выбор нескольких спутников сохраняется между запусками.

---

# 15. Min Elevation

Для прогноза можно задавать минимальный угол места.

Он используется как реальная граница пролёта.

Например:

- Min EL = 0° — геометрический горизонт;
- Min EL = 5° — AOS наступает при подъёме выше 5°, LOS — при уходе ниже 5°.

---

# 16. Расчёт AOS / LOS

Pass Predictor использует:

1. пошаговый поиск интервала пересечения заданного угла места;
2. последующее уточнение пересечения бинарным поиском.

Поэтому итоговое время AOS/LOS не ограничено грубым первоначальным шагом поиска.

Небольшое различие в несколько секунд относительно других спутниковых программ возможно из-за:

- другой реализации SGP4;
- немного другой модели наблюдателя;
- высоты QTH;
- Min Elevation;
- используемого TLE;
- алгоритма определения момента пересечения горизонта.

---

# 17. Счётчик AOS / LOS

На странице ROTATOR работает живой счётчик.

Если спутник ниже горизонта:

`AOS через HH:MM:SS`

Если пролёт уже идёт:

`До конца пролёта HH:MM:SS`

После LOS приложение автоматически начинает отсчитывать время до следующего AOS.

---

# 18. Звуковые сигналы AOS / LOS

Kepler Orbit может подавать звуковые сигналы начала и окончания пролёта.

AOS и LOS имеют разные звуковые последовательности.

Звук генерируется приложением через Android AudioTrack.

---

# 19. Yaesu G-5500 / GS-232B

Встроена поддержка управления антенным ротатором **Yaesu G-5500** через GS-232B-совместимый контроллер.

Поддерживаются:

- USB / OTG;
- Wi-Fi / TCP.

---

# 20. USB / OTG

Программа может работать с USB-UART / GS-232B-контроллером через Android USB Host.

Используется библиотека:

`usb-serial-for-android`

Есть режим USB RAW TEST для диагностики:

- наличия USB-устройства;
- открытия порта;
- обмена командами;
- получения ответов контроллера.

---

# 21. Wi-Fi / TCP

Можно подключаться к GS-232B-контроллеру через TCP.

Настраиваются:

- IP-адрес;
- TCP-порт.

Типичное значение порта проекта:

`4533`

---

# 22. ROTATOR FEEDBACK

Программа регулярно запрашивает фактическое положение ротатора.

Отображаются:

- AZ;
- EL.

Обратная связь работает:

- в AUTO TRACK;
- во время PARK;
- при ручном перемещении;
- при подключённом ротаторе в режиме ожидания.

---

# 23. AUTO TRACK

START AUTO TRACK запускает автоматическое сопровождение выбранного спутника.

Программа:

- рассчитывает текущие AZ / EL;
- сравнивает их с последней отправленной целью;
- отправляет новые команды GS-232B только при необходимости;
- контролирует минимальный угол места;
- продолжает читать фактическое положение ротатора.

При активном режиме кнопка превращается в:

`STOP AUTO TRACK`

---

# 24. Независимый шаг AZ / EL

Можно выбрать шаг:

- 1°;
- 3°;
- 5°;
- 7°;
- 10°.

Порог применяется независимо к каждой оси.

Пример при шаге 3°:

- AZ изменился на 3° → обновляется AZ;
- EL изменился только на 1° → целевое EL остаётся прежним.

Это уменьшает частые мелкие движения редуктора.

---

# 25. P36 / P45

Поддерживаются режимы:

## P36

Азимут до 360°.

## P45

Азимут до 450°.

Выбранный режим учитывается при автоматическом и ручном управлении.

---

# 26. Ручное управление

Можно вручную задать:

- AZ;
- EL.

И отправить GS-232B-команду:

`Waaa eee`

---

# 27. STOP

Отдельная кнопка останавливает движение ротатора.

---

# 28. PARK ROTATOR

Можно сохранить парковочную позицию:

- PARK AZ;
- PARK EL.

Команда PARK ROTATOR отправляет антенну в эту позицию.

Настройки сохраняются.

---

# 29. PARK AFTER LOS

При включённой функции:

1. спутник сопровождается;
2. происходит LOS;
3. AUTO TRACK останавливается;
4. ротатор автоматически отправляется в PARK.

Функция выполняется один раз после окончания конкретного пролёта.

---

# 30. KEEP SCREEN ON

Опция KEEP SCREEN ON не позволяет Android погасить экран во время работы приложения.

Используется системный:

`FLAG_KEEP_SCREEN_ON`

Отдельное разрешение WAKE_LOCK не требуется.

Настройка сохраняется.

# 35. Общая схема работы

Типичный порядок использования:

1. загрузить TLE;
2. выбрать спутник;
3. задать QTH;
4. проверить текущие AZ / EL;
5. открыть PASSES;
6. выбрать интересующие спутники;
7. включить ALL SELECTED при необходимости;
8. выбрать стиль карты;
9. выбрать вид 3D: TRACK / QTH / SUN / MOON;
10. при работе с ротатором подключить GS-232B;
11. проверить ROTATOR FEEDBACK;
12. запустить AUTO TRACK.

# 37. Примечания

Kepler Orbit создаётся как радиолюбительский и экспериментальный проект.

Перед подключением реального ротатора рекомендуется проверить:

- механические пределы антенны;
- направление AZ / EL;
- соответствие режима P36 / P45;
- PARK-позицию;
- работу STOP;
- корректность обратной связи;
- правильность выбранного TLE;
- правильность QTH.

Приложение не следует использовать как единственный источник данных в задачах, где требуется сертифицированная навигационная или космическая точность.
